The files in this directory are older versions of the XML from before I messed up the nesting of the tags by trying to make it easier to convert names to wikilinks. The tags in these files are much more logically and consistently nested but the keys for linkage of place names are different from, and probably not as good as, the newer version of the XML in the parent directory. Each file corresponds to one original account book in SP 28/131. The part number should be obvious from the file name.

XML tags in these older files are mostly the same as in the newer file in the parent directory. These older files have an extra `<group>` tag which groups together owners who share an `<address>` or `<status>`. The child tags of each `<group>` tag should include at least two `<owner>` tags and at least one `<status>` or `<address>`. This is intended to imply that a `<status>` or `<address>` that is a child of a `<group>` applies equally to all sibling `<owner>` tags. I don't think this is an ideal way of representing these relationships, but it was the best I could think of within the constraints of XML given the way that they are written in the original text.

Please note that the XSL files in the parent directory **will not** work properly with these older XML files.
